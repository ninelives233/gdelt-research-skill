# 人工复现与可读交付

交付应让初学者既能理解结果，也能自己重复关键步骤。阅读版服务于查看，原始文件和记录服务于核查；两者通过记录 ID、原文链接或来源包关联，不覆盖机器原值。

## 人工复现指引

每次按实际操作生成一份中文指引，并在阅读版首页或交付消息中链接它。至少包含以下内容：

1. **范围与结果是什么**：研究主题、起止时间、时区、数据类别、每行含义、语言范围及取样方式。区分事件发生日期、GDELT 收录时间和原包更新时点；列出实际取得与未取得的数据。
2. **从哪里进入**：提供可点击的官方网页入口和本次实际使用的查询 URL 或原始 ZIP URL。写出关键词与参数，不仅给一个网站首页。多包采集附清单，选择其中一个成功包作为手工演练，并说明它不能代表完整范围。
3. **怎样操作**：按“打开哪个页面 → 填什么 → 选哪个日期范围 → 点什么 → 保存成什么”写步骤。界面文案以实际核对为准；未验证的按钮或路径标明未验证。对于直接下载，写“点链接下载 ZIP → 解压 → 按制表符导入”，不要假装存在主题搜索按钮。
4. **怎样筛选**：把技术规则翻译成动作，保留精确表达供核对。说明关键词、主题与国家条件是同时满足还是任选其一，是否双向、是否去重，以及哪部分是机器条件、哪部分仍待人工判断。阅读版中的主题分类或翻译要与原字段区分。
5. **怎样导入并检查**：说明文件编码、分隔符、无表头时的字段映射、代码列的文本类型、链接列，以及打开后的预期列。举一两条真实记录，演示检查日期、来源和相关性。列数与记录数须来自本次实测。
6. **怎样核对复现结果**：记录从原始记录到筛选、去重、核心候选各阶段的数量与规则。对应 CSV、工作表和图表说明筛选范围；记录 URL、查询时间、原包名称和校验值。实时接口结果可能变化，给出差异排查方法，不承诺永远得到相同行数。
7. **遇到失败怎么办**：说明本次实际出现的限流、缺包或解析失败，保留失败清单。缺失不是零；换下载方式后若语言、时间覆盖或采样总体不同，必须解释，不能称为完全相同的替代结果。

### 直接下载原始包的手工演练

以下是演练格式，正式交付应替换为实际成功下载的批次和筛选条件。若本次确实使用了此批次，可以直接采用。

1. 在浏览器打开 [2018-07-06 12:00 UTC 的 GKG 原始包](https://data.gdeltproject.org/gdeltv2/20180706120000.gkg.csv.zip)，保存 ZIP 并解压。这只是一个 15 分钟更新批次，不是当天全量。
2. 在 Excel 通过“数据 → 从文本/CSV”或对应版本的文本导入入口选择解压文件。扩展名虽然叫 CSV，实际是**制表符分隔**；选择 UTF-8，把代码、ID 和日期码按文本导入。原始包无表头，按本次附带的“列号—原字段—中文含义”对照表添加列名，避免把首条数据当成列名。
3. 查看 `Themes`（主题标签）和 `V2Locations`（文中提到的地点）。本例要求主题中精确包含 `ECON_TRADE_DISPUTE`，并且地点中同时存在中国 `CH`、美国 `US`。解释这些代码后再要求用户操作。
4. 准确手工复现可使用 Power Query 等表格拆分功能：主题按分号拆成单独标签后做精确匹配；地点先按分号拆成多条，再按 `#` 拆列，第三项为国家代码，分别筛出 `CH`、`US` 的记录 ID 后取交集。先保留原始 ID，以便拆分后合并并去重。用户不熟悉该工具时，把步骤展开到本次实际界面，并给出筛选中间表；不要用在整行搜索“CH”和“US”冒充精确国家筛选。
5. 打开阅读版的原文链接，检查是否真的讨论中美贸易争端。只命中机器条件的行仍标“候选，待核验”。比较手工筛出的记录 ID 与程序输出；核对差异是否来自拆分、去重或二次相关性筛选。

对于 Events，采用对应 `.export.CSV.zip` 链接，导入后筛选参与方国家字段：`CHN → USA` 或 `USA → CHN`。两种方向取并集，解释“中美互动”不等于“贸易战”，再进行实际使用的贸易相关性筛选。

对于 DOC，提供实际查询 URL，解释关键词、时间参数和返回上限。若提供 CSV 下载链接，确认返回正文是数据而不是 429 错误。Summary 多组件同时请求可能限流，初次演练可以只看一个列表或图表；再次失败时保留说明，原始包路径也不保证服务永远可用。

## 中文阅读版的布局

初学者面对多类结果时，通常提供一个中文 Excel，加一份操作指引；若只取得少量记录，简明的中文预览表和指引即可。用户明确要求的文件格式优先。只使用本次实际取得的数据，不要求每次都做下面所有页面。

| 阅读区域 | 让用户先看到什么 | 核查和说明 |
|---|---|---|
| 概览／先看这里 | 研究范围、数据类别、各自记录数、每行含义、阅读顺序、关键图表 | 显示缺失、采样或语言限制，链接操作指引；不同单位分开统计，不合成一个“总数据量” |
| 新闻导读 | 清晰时间、中文标题、阅读主题、来源、可点击的原文链接、复核提示 | 原文标题另列保留；译文标明用途，不据 URL 编造缺失标题；自动分类、标题初读和全文核验分开 |
| 报道趋势 | 日期、匹配报道数、监测基数、关注度、覆盖状态及趋势图 | 明确 UTC 或北京时间；缺失不填零、图线不跨缺口暗示连续观测 |
| 事件解读 | 事件日期、参与方、通俗行为说明、关联新闻、待复核原因 | 原事件代码与 ID 可追溯；行为说明有代码依据，不能把 Goldstein 解释成经济损失 |
| 文章情绪 | 标题、来源、整体语调、数值、链接和说明 | 说明这是文章整体语气，不是对某国的立场；区分机器事件的 AvgTone 与文档的 V2Tone |

采用清晰列宽、自动换行、冻结标题、表格筛选和便于阅读的日期格式。长网址显示为“阅读原文”等短标签，同时保留真实目标。可把低频机器字段放在后面或单独的原始表，用户阅读的主要列不要被几十个代码淹没。

新闻标题为外语且阅读版面向中文初学者时，为主要阅读范围提供中文译文并保留原文。没有可靠标题时写“标题未取得”，使用真实链接核查；译文和自动阅读提示不等于核实新闻事实。大量结果可以提供范围明确的核心阅读页，附全量候选文件，不能把精简阅读页假称全部结果。

## 可视化口径

- 用时间序列展示变化，用条形图比较可比类别；只要一张表就能读清时不强行画图。科研或可导出的图表保存为独立 PNG／SVG 等文件，按用户需要嵌入报告或工作簿。
- 图题与注释写清主题、统计单位、时间范围、时区、语言流、采样层及数据来源。候选数、不同新闻 URL 数、机器事件数、原包记录数分别命名。
- 关注度为匹配报道数除以全部监测报道数。月度关注度若由日度原始量计算，用相同有效日期的分子之和除以分母之和；不要简单平均每日百分比。有缺失时注明“仅已返回日期”，不要标成完整月度。
- 全日 DOC 趋势与固定时点原包样本不能当作同一个统计总体。固定周一层与政策日补点若混合，须说明抽样设计；优先分别展示，不能据目的性抽样推算事件总量。
- 缺失日期保留覆盖状态，图中断线或留空；无相关报道的真实零值另行表示。不得用插值填出未观测数据再画成实测。样本情绪均值注明单位、样本数与聚合方法，不能替代全日情绪。
- 不用情绪或事件图表暗示已证明金融安全的变化或因果影响；需要外部金融变量与独立研究设计时另行说明。

## 交付前检查

1. 从原始结果独立核对概览、阅读表和图表的数量、日期及单位；检查去重与核心候选筛选是否解释了行数差异。
2. 逐项走通一个代表性批次的人工路径；将实际验证与根据文档描述的步骤区分，不把脚本成功说成人工界面也已验证。
3. 对新建或修改的阅读版和图表渲染预览，检查中文字体、长标题、列宽、数字、时间轴、图例和注释，修复遮挡或截断。检查筛选范围、冻结标题和原文链接的真实目标，不能只看渲染后像不像链接。环境无法完成某项检查时明确说明。
4. 最终消息先给阅读版、操作指引和关键发现／缺口；原始包或证据目录作为可追溯附件。不要让用户从一堆脚本和原始路径中猜该打开哪个文件。
